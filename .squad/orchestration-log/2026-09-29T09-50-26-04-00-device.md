## Key context

This was the fourth confirmed instance of the same systemic defect class: the simulator accepted a value domain the vendor hardware could not honour. Vendor ilib.camera_start() takes no size argument, camera_clone() hardcodes 640x480, and no-camera startup returns from a background thread without raising. CameraPort.start(width=, height=) had promised caller-chosen dimensions; the adapter stored and silently dropped them while the simulator honoured them.

The fix moved the camera size constraint into the shared contract layer: VILIB_CAPTURE_SIZE and alidate_camera_resolution() in ports.py, called by both adapter and simulator before any side effect. The work also added camera_available() to both layers, SimulatedCamera(available=False) for camera-less testing, teardown when camera_start() fails, and an actionable timeout message.
