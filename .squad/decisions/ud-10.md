Title: UD-10 — Azure broker mandatory vs direct short-lived-token Speech path
Status: Accepted
Decision: Option 3 — Hybrid, gated-by-policy
Decision date: 2026-09-08
Related issue: #20
Decision owner (provisional): @dmd0822
Target resolution date: 2026-09-22

Context
- Issue #20 tracks whether the Azure broker must be used for all cloud calls or whether a direct short-lived-token Speech evaluation path may be permitted. This affects security boundaries, threat surface, and M2 scope.
- Current implementation uses brokered calls for token exchange and auditing; a direct path could reduce latency and complexity for short-lived evaluations but may relax central auditing and increase token-handling surface.

Options

1) Broker-mandatory (Safer, default)
- Description: Require all Speech and cloud calls to go through the Azure broker.
- Pros: Centralized auditing, easier RBAC and policy enforcement, consistent telemetry, smaller surface for secrets/token handling in services.
- Cons: Slightly higher latency, broker operational cost, single path dependency.

2) Allow direct short-lived-token Speech path (Performance-first, conditional)
- Description: Allow a direct path for short-lived Speech evaluations using tightly-scoped tokens, with controls: short TTL, strict logging hooks, and mandatory review of callers.
- Pros: Lower latency for short-lived evaluations, simplified client flow for some workloads.
- Cons: More complexity to secure token issuance, higher risk of token leakage, more places to enforce auditing.

3) Hybrid, gated-by-policy (Recommended compromise)
- Description: Default to broker-mandatory. Permit direct path only for approved services under a gated policy (review + automated controls): enforce short TTL, ephemeral credentials, mandatory structured logging, and quarterly entitlement review.
- Pros: Balances security and performance; keeps centralized control for most flows while enabling optimized paths where justified.
- Cons: Adds policy management overhead and review processes.

Recommendation
- Adopt option 3 (Hybrid, gated-by-policy). Make the broker the default safe path and allow direct short-lived-token Speech evaluations only after explicit entitlement, automated controls (TTL <= 60s, structured telemetry), and documented design review.

Owner
- Provisional owner: @dmd0822 — request confirmation. If unavailable, escalate to the Architect (team lead) for final assignment.

Consequences
- Immediate: implement broker-by-default in code and docs; add gating checks for direct path requests.
- Implementation work: small API changes for entitlement and token TTL checks, logging hooks, and test coverage for both paths.
- If accepted: reduces risk while permitting optimized flows when justified. If rejected: keep broker-only approach and close UD-10 as "Broker mandatory".

Notes
- This decision recommends operational controls (TTL, telemetry, quarterly review) to minimize risk when enabling direct paths.
