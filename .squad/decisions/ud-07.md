# UD-07 — Conversation retention decision

Status: Proposed
Related issue: #17
Decision owner: @dmd0822 (provisional)
Target resolution date: 2026-09-22

## Context
Purpose: define whether the device retains conversations or other state across sessions and how it is deleted. Context: this decision is tracked from issue #1 and affects privacy, RAI, and the data-management plan. Acceptance criteria: the retention policy is recorded, the decision is linked from the M0 tracking doc, and any follow-up policy or implementation work is captured.

## Options

### Option A — No persistent retention (Safer, Recommended)
- Description: Do not persist conversations beyond the active device session. All conversation state is in-memory and cleared on app/device restart or explicit user action.
- Pros: Best privacy and compliance posture; minimal RAI surface; simplest to audit and implement.
- Cons: Reduced UX continuity across sessions; users cannot resume past conversations.

### Option B — Short-term ephemeral retention with TTL
- Description: Retain conversations for a short configurable TTL (e.g., 24–72 hours) encrypted at rest; auto-delete after TTL and allow explicit user deletion.
- Pros: Balances UX and privacy; allows short-term resumption.
- Cons: Increased compliance burden; requires secure storage and deletion support.

### Option C — Persistent retention with explicit opt-in
- Description: Persist conversations until user deletes them; retention enabled only after explicit consent and visible controls.
- Pros: Best UX for continuity and features that rely on history.
- Cons: Highest privacy and RAI risk; requires robust policy, consent tracking, and deletion workflows.

## Recommendation
Recommend Option A (No persistent retention). This is the conservative choice that minimizes privacy and RAI risk while keeping implementation and audits straightforward. If user experience needs arise, revisit and adopt Option B with strict controls.

## Owner
Provisional owner: @dmd0822

## Consequences
- Implementation: Ensure in-memory-only conversation handling; add clear UI/UX messaging that conversations are not retained across sessions.
- Policy: Update M0 tracking doc with link to decision; record follow-up tasks for any required compliance documentation.
- Follow-ups: If later adopting TTL or persistent retention, create a new UD for storage, encryption, consent, and deletion workflows.
