# UD-11-ud-01 — Hardware decision (Proposed)

Status: Proposed
Related issue: #11
Decision owner: @dmd0822 (provisional)
Target resolution date: 2026-09-22

Context
-------
Issue #11 tracks the hardware choice for the project's first release. This decision blocks M1 exit and M5 entry and was raised to resolve exact hardware constraints and acceptance criteria for the release. The issue summary: "Resolve UD-01: exact hardware decision" (created 2026-08-31).

Options
-------
1) Raspberry Pi 4 (4GB) as baseline
   - Pros: widely available, strong community support, low-cost, sufficient CPU for edge tasks and local audio processing
   - Cons: thermal/perf limits under sustained load; peripheral power/IO limitations for high-actuator designs

2) Raspberry Pi 5 or PiDog-class (higher-spec SBC)
   - Pros: better CPU/GPU, more RAM, improved thermals, headroom for advanced local ML inference
   - Cons: higher cost, potential supply variability, larger power profile

3) Hybrid: Pi 4 for baseline + cloud-offload for heavy inference (documented fallbacks)
   - Pros: lowest upfront HW cost, flexible scaling via cloud; easiest to procure
   - Cons: depends on reliable network; increased operational cost and privacy considerations

Recommendation
--------------
Recommend Option 3 (Hybrid): select Raspberry Pi 4 (4GB) as the baseline development and field unit for M1, with a documented cloud-offload architecture for heavier ML inference. This balances cost, availability, and immediate developer velocity while preserving an upgrade path (Pi5/PiDog) for M5 or premium SKUs.

Owner
-----
Recommendation owner: @dmd0822 (provisional). Squad Architect and Reliability should review and either approve or propose an alternative within 14 days.

Consequences
------------
- Short-term: enables M1 progress with readily available hardware and predictable BOM cost.
- Mid-term: cloud-offload requires specifying the network, privacy, and cost model in follow-up tasks; add a follow-up ticket to document cloud API, retry/backoff, and data handling.
- If supply or performance proves insufficient, upgrade path to Pi5/PiDog is available but requires a targeted QA pass and a BOM delta.

Notes
-----
- If the team prefers a Pi5-first strategy for on-device inference, note that this raises BOM cost and may shift schedule to include additional hardware QA.
- This record is proposed; please confirm or reassign the decision owner in the issue comment.
